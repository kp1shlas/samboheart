БАГ-6. approve_certificate затирал отметки «Был» (present → excused), стирая

ЧАСТЬ 2. ЧТО ИЗМЕНЕНО (файлы)
════════════════════════════════════════════════════════════════

1) core/services/certificates.py — ПОЛНОСТЬЮ ПЕРЕПИСАН:
   - approve_certificate(): возвращает занятия на баланс ЗАПИСИ В ГРУППУ
     (ChildEnrollment.remaining_lessons), а не в Child. Возвращает занятия
     ТОЛЬКО если оно реально было списано (was_deducted=True). Отметки
     «Был» не трогает. Идемпотентен (повторный вызов = 0). Всё внутри
     transaction.atomic() + select_for_update.
   - reject_certificate(): возвращает «не был» только по датам, НЕ
     покрытым другой одобренной справкой; списывает занятие только если оно
     ранее возвращалось справкой (was_deducted=False) И баланс > 0 —
     баланс НИКОГДА не уходит в минус. Идемпотентен.
   - Статус справки (approved/reviewed_at) теперь выставляет сам сервис.

2) core/services/debts.py — ПЕРЕПИСАН:
   - Новая функция credit_lessons_on_payment(payment): при оплате просто
     начисляет payment.lessons_count на enrollment.remaining_lessons.
     Логика is_debt УДАЛЕНА. Платёж блокируется select_for_update, всё в
     транзакции — webhook + возврат пользователя не начислят дважды.
   - settle_debts_on_payment() оставлен как псевдоним для совместимости
     (возвращает debts_settled=0).

3) core/views.py:
   - attendance_sheet_for_lesson: удалена вся is_debt-логика. Новая схема
     сохранения (в transaction.atomic, записи блокируются):
     а) если was_deducted=True — вернуть ровно 1 занятие (когда было
        списано, столько и возвращаем — баланс не дублируется);
     б) списание только при статусе «не был», наличии записи в группу,
        не-бесплатной скидке и балансе > 0 (без минуса);
     в) was_deducted теперь отражает ФАКТИЧЕСКОЕ списание, а не желаемое.
   - В контекст добавлен enrollment_map — колонка «Остаток» в табеле
     теперь показывает реальный остаток по записи в группу.
   - child_detail и child_dashboard: удалён расчёт и вывод «Занятия в долг»
     (debts_count).
   - Все места начисления по оплате переведены с settle_debts_on_payment на
     credit_lessons_on_payment (payment_success, payment_mock_success,
     payment_mock_confirm, owner_cash_payment, tochka_webhook) + понятные
     сообщения, если запись в группу не найдена.
   - owner_certificates: статус выставляет сервис (идемпотентность).

4) core/admin.py:
   - CertificateAdmin: действия «Одобрить»/«Отклонить» больше не ставят
     статус сами — делегированы сервису.
   - PaymentAdmin.save_model: начисление через credit_lessons_on_payment.
   - AttendanceAdmin и AttendanceInline: is_debt убран из интерфейса

5) templates/child_detail.html — удалён блок «Занятия в долг».
6) templates/attendance_sheet.html — колонка «Остаток» исправлена на

ЧАСТЬ 4. ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ ЛЕГАСИ-ДАННЫХ (важно прочитать)
════════════════════════════════════════════════════════════════

1) Из-за БАГ-2 в старых данных есть записи was_deducted=True, по которым
   занятие на самом деле НЕ списывалось (баланс был 0, срабатывал clamp).
   Если по такой записи преподаватель сменит статус на «Был», баланс
   увеличится на 1 незаслуженно. Рекомендуется разовая сверка:
   Attendance.objects.filter(was_deducted=True, is_debt=False) сверить с
   платежами. Можно также вручную выставить was_deducted=False в админке.
2) Старые «долги» (is_debt=True) больше не погашаются при оплате — оплата
   просто начисляет занятия. Если родитель с долгом уже оплатил по старой
   логике (долг погашен флагами), баланс уже соответствует.
3) Справка, одобренная ДО этого исправления, повторно обработана не будет
   (идемпотентность по статусу). Если старая справка «упала» с ошибкой и
   статус остался pending — её можно безопасно одобрить заново.

РЕЗЮМЕ ПОВЕДЕНИЯ (новые правила баланса)
════════════════════════════════════════════════════════════════

- Списание: только «не был» + есть активная запись в группу + не
  бесплатная скидка + баланс > 0. Иначе занятие не списывается (без долга,
  без минуса).
- Возврат: только за реально списанное (was_deducted=True).
- Оплата: просто начисляет lessons_count на баланс записи.
- Справка: approve возвращает списанное; reject списывает возвращённое;
  обе операции идемпотентны и атомарны.
